RATL Specification

RATL (R Array ManipulaTion Language) is a stack-based, esoteric programming language inspired by MATL. It leverages R’s powerful statistical and matrix capabilities through a concise, postfix syntax, making it highly suitable for code golf.

Total symbols: 421 (all 2-byte or shorter)

Getting Started

RATL programs are sequences of tokens evaluated left to right on a stack. No variable declarations, no semicolons — just push values and apply operations.

Basic Arithmetic

3 5 +       → 8        # push 3, push 5, add
10 3 /      → 3.333...  # divide
2 3 ^       → 8        # power

Arrays

[1 2 3] l    → 3        # length
[1 2 3] s    → 6        # sum
[1 2 3] m    → 2        # mean
[3 1 2] O    → 1 2 3    # sort

Blocks (Higher-Order Functions)

[1 2 3] {2 *} q    → 2 4 6      # map: double each
[1 2 3 4] {2 %} e  → 2 4         # filter: keep evens
[1 2 3 4] {+} y    → 10          # reduce: sum

Control Flow

3 5 > ? 'yes' ; 'no' ]    → 'no'    # conditional
1 5 ( p )                  → 1 2 3 4 5  # for-each

Language Overview

Design Philosophy

RATL is designed as a stack-based array manipulation language for code golf. Its core model is:

  1. Stack — all operations work on a single global stack
  2. Arrays — the primary data structure for bulk operations
  3. Blocks — first-class code fragments for higher-order operations

Symbol Tiers

RATL organizes its symbol set into three conceptual tiers:

Tier 1 — Core (stack manipulation, arrays, blocks, control flow, arithmetic)
107 symbols across 5 categories
Tier 2 — Toolkit (grouping, mapping, reduction, matrix operations, strings, sets)
67 symbols across 4 categories
Tier 3 — Extensions (statistics, distributions, filesystem, shell access, meta-programming)
213 symbols across 7 categories

The Stack

RATL uses a single global stack (an R list). Every operation interacts with this stack — pushing, popping, or transforming elements.

Stack Notation

Throughout this specification, stack effects are described using the notation:

  • $1 — top of stack (most recently pushed)
  • $2 — second element from top
  • $n — nth element from top
  • n → m — operation consumes n elements, produces m elements

For example, + has stack effect 2 → 1: it pops two values and pushes their sum.

Stack Manipulation Primitives

Symbol Name Description Stack Effect
D Duplicate Copies the top element 1 → 2
w Swap Swaps the top two elements 2 → 2
x Delete Removes the top element 1 → 0
U Unpack Pushes each element of an array onto the stack individually 1 → n
Ls Stack Length Pushes the current number of elements on the stack 0 → 1

Clipboards

RATL provides four clipboards for temporary storage outside the stack:

  • H, G, L, M — each holds one value independently of the stack
  • Useful for saving intermediate results without stack gymnastics

Literals

Literals are pushed onto the stack as soon as they are encountered during parsing.

Numbers

Standard numeric notation: 1, 10, 3.14, -5.

Numerical Arrays (Vectors)

Enclosed in square brackets [...]. Elements are separated by spaces. Example: [1 2 3] pushes a numeric vector of length 3.

Character Arrays (Strings)

Enclosed in single quotes '...'. Example: 'hello' pushes a character vector of length 1.

Cell Arrays (Lists)

Enclosed in curly braces {...}. Example: {1 'a' [1 2]} pushes an R list containing three different types.

Blocks and Evaluation Model

Blocks are first-class code fragments enclosed in {...}. They are not executed when pushed — they are pushed as values and later consumed by higher-order operators.

Block Creation

{2 *}    → pushes a block onto the stack (value, not execution)
{+}      → pushes a block that adds the top two elements

Block Consumption

Blocks are consumed by operators that pop them from the stack:

Operator Name Behavior
{block} array q Map Applies block to each element, collects results into array
{block} array e Filter Keeps elements where block returns truthy
{block} array y Reduce Folds array left using block as binary operator
N {block} z Repeat Executes block N times, returns last result
{block} @ Execute Pops and executes a block immediately
{block} array zB Sort By Sorts array using block as key function
{block} array zG Group By Groups array elements by block’s return value
{block} array zC Scan Like reduce, but returns all intermediate results
{block} array zT Take While Takes elements while block returns truthy
{block} array zW Drop While Drops elements while block returns truthy
{block} A B zZ Zip With Applies block pairwise to two arrays

Execution Environment

When a block executes, the following rules apply:

  1. Stack access: The block can read the stack via $1, $2, etc.
  2. Element binding: For q, e, zB, zG, zT, zW — the current element is pushed before block execution, available as $1
  3. Return value: The last value remaining on the block’s internal stack after execution is the result
  4. Stack isolation: The block’s internal stack operations do not leak into the outer stack — only the return value is pushed back
  5. Nesting: Blocks may contain other block literals; nested blocks are pushed as values, not executed

Examples

# Map: double each element
# Block {2 *} receives each element as $1
[1 2 3] {2 *} q    → [2 4 6]

# Filter: keep positive numbers
# Block {0 >} receives each element; truthy keeps it
[3 -1 4 -2] {0 >} e    → [3 4]

# Reduce: sum
# Block {+} receives accumulator as $2, current element as $1
[1 2 3 4] {+} y    → 10

# Sort by: absolute value
# Block {0-} computes key for each element
[3 -1 4 -2] {0-} zB    → -1 -2 3 4

# Execute: run immediately
{3 5 +} @    → 8

Truthiness

RATL follows R’s truthiness rules. Truthiness is used by control flow (?), filter (e), while loops (double-quote), take-while (zT), and drop-while (zW).

Falsy values:

Value Reason
FALSE Boolean false
0 Numeric zero
"" Empty string
NULL Null value
NA Missing value
numeric(0) Empty numeric vector
character(0) Empty character vector
logical(0) Empty logical vector

Truthy values: everything else, including:

  • TRUE
  • Any non-zero number (positive or negative)
  • Any non-empty string
  • Any non-empty vector or list
  • Matrices and data frames

Edge case — NA: In R, NA is neither TRUE nor FALSE, but for RATL control flow it is treated as falsy.

Control Flow

Conditional Branching (? ... ])

  • ? starts a conditional block, ] ends it
  • If-Else: ? condition ; then-branch ; else-branch ]
  • Behavior: Pops the top element. If truthy, executes until first ; or ]. If falsy, skips to the ; branch (if present) or skips to ].
1 ? 'yes' ; 'no' ]        → 'yes'    # truthy
0 ? 'yes' ; 'no' ]        → 'no'     # falsy
0 ? 'yes' ]                → (empty)  # no else branch

While/Repeat Loop (" ... ")

  • Symbol: " (opening and closing)
  • Behavior: Executes the loop body. At the closing ", pops the top element. If truthy, repeats from the opening ". If falsy, exits the loop.
3 " 1 - D p "    → 3 2 1    # counts down

For-Each Loop (( ... ))

  • ( pops an array/list, ) marks the end
  • Behavior: Iterates through each element, pushing it onto the stack and executing the body.
[1 2 3] ( p )        → 1 2 3    # prints each element
[3 5 7] ( D + )       → 6 10 14  # doubles each

Infinite Loop (` ... `)

  • Symbol: ` (backtick, opening and closing)
  • Behavior: Executes the body repeatedly. Use X (break) to exit the loop.
` 'quit' i X `        → 'quit'    # reads until 'quit'

Statements and Separators

  • Space: Acts as a token separator.
  • Newline: Ignored by the parser but acts as a token separator.
  • Comments: Lines starting with # are treated as comments and ignored.

Implicit Actions

Initial Actions

  • The stack is initialized as an empty list().
  • A connection to stdin is opened for input operations.

Final Actions

  • Implicit Print: If the stack contains exactly one element, it is printed automatically. If it contains more than one, the entire stack is printed as a list.
  • Invisible Output: The final evaluation result is returned invisibly in R.

Meta-Programming

RATL supports meta-programming — code that generates or manipulates other code at runtime.

Dynamic Evaluation (ev)

Pops a string from the stack and executes it as RATL code:

'3 5 +' ev        → 8
'[1 2 3] s' ev    → 6
'5 fp' ev         → 120

Dispatch List (zD)

Pushes a list of all available symbol names onto the stack:

zD    → [+ - * / D w x ...]

Dynamic Dispatch (zS)

Calls a symbol by name (string):

3 5 '+' zS    → 8
5 'sq' zS     → 2.236...

Shell Exec (zX)

Runs a shell command and pushes the output:

'echo hello' zX    → "hello"
'ls' zX            → file listing

Sort By (zB)

Sorts an array using a block as the key function:

[3 1 4 1 5] {0-} zB    → 1 1 3 4 5 (reverse sort)
[1 2 3] {2 *} zB       → 1 2 3

Group By (zG)

Groups array elements by the block’s return value:

[1 2 3 4 5 6] {2 %} zG    → $0: [2 4 6] $1: [1 3 5]

Scan (zC)

Like reduce, but returns all intermediate results:

[1 2 3 4 5] {+} zC    → 1 3 6 10 15
[2 3 4] {*} zC        → 2 6 24

Take While (zT)

Takes elements while the block returns truthy:

[1 2 3 4 5] {4 <} zT    → 1 2 3

Drop While (zW)

Drops elements while the block returns truthy:

[1 2 3 4 5] {3 <} zW    → 3 4 5

Zip With (zZ)

Applies a block pairwise to two arrays:

[1 2 3] [4 5 6] {+} zZ    → 5 7 9

Error Handling

RATL propagates R errors when operations fail. Common error conditions:

Condition Error Example
Stack underflow stack underflow x on empty stack
Type mismatch non-numeric argument + applied to strings
Divide by zero Returns Inf or NaN 1 0 /
Index out of bounds subscript out of bounds el with invalid index
Malformed block unexpected } {2 * (missing closing })
Invalid file path cannot open connection F with nonexistent path

Formal Grammar

program     ::= statement*
statement   ::= literal | symbol | block

literal     ::= number | array | string
number      ::= [ '-' ] DIGIT+ [ '.' DIGIT+ ]
array       ::= '[' statement* ']'
string      ::= Apostrophe { NOT_APOSTROPHE } Apostrophe

block       ::= '{' statement* '}'

symbol      ::= <any 1-2 character token not matching the above>
comment     ::= '#' { NOT_NEWLINE } NEWLINE

# Whitespace rules:
# - Space and newline act as token separators
# - Newlines are otherwise ignored (not significant)

Design Rationale

Why R?

R provides powerful statistical computing, matrix operations, and a rich standard library. This lets RATL achieve golf-friendly conciseness for mathematical and statistical tasks that would require hundreds of characters in other languages.

Why Stack-Based?

Stack-based languages eliminate the need for variable names and assignment syntax. In code golf, every character counts — a stack model means 3 5 + instead of result = a + b.

Why These Control Flow Delimiters?

The delimiters (?, ], (, ), ", `) were chosen for single-character compression. Block delimiters { and } follow convention and remain memorable.

Why Not Purely Functional?

RATL mixes functional higher-order operations with imperative stack manipulation because R itself is multi-paradigm. This pragmatic approach maximizes expressiveness for golf.

Implementation

RATL is implemented in R and uses R’s internal data structures (vectors, lists, matrices) to handle stack operations. It translates RATL code into R code, which is then evaluated. An alternative implementation would need to replicate this stack-to-R-code translation.
